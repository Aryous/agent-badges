## 2. 新徽章与解锁条件

「会话」在 Claude Code 指自己发起的主会话（不含子代理，`isSidechain` 为假），在 Codex 指自己发起的线程（vscode / cli / exec，不含子代理和审查）。时间一律按本地时区。

### 2.1 习惯（两边都有）

| id | 名称 | 解锁条件 |
| --- | --- | --- |
| `midnight-crossing` | 跨日夜战 | 同一个会话在 D 日 23:00 前有活动，在 D+1 日 02:00 后也有活动，且 23:00–02:00 之间相邻两次活动的间隔都不超过 60 分钟 |
| `productive-day` | 高产日 | 一天内开启 ≥ 20 个会话 |
| `multitasker` | 多线并行 | 某一时刻有 ≥ 3 个会话同时处于活动中。会话的活动区间：相邻两次活动间隔 ≤ 10 分钟就连成一段 |
| `perfect-month` | 全勤月 | 某个自然月的每个周一到周五都有活动。当月只有在最后一个工作日过完后才判定；不扣法定节假日 |

和现有徽章的区别：
- 「跨日夜战」要求同一会话连续跨过午夜。「夜猫子」只要 0–5 点有活动就算。
- 「全勤月」替代原提议的「全勤周」，因为全勤周比「七日连击」还容易拿到。

### 2.2 里程碑（4 级：铜 / 银 / 金 / 顶级三款随机）

| id | 名称 | 品牌 | 门槛 | 计数来源 |
| --- | --- | --- | --- | --- |
| `active-hours` | 协作时长 | 两边 | 10 / 100 / 1000 / 5000 小时 | 所有会话活动时间的并集。相邻两次活动间隔 ≤ 30 分钟的部分计入，超过的不计；多个会话同时进行只算一次 |
| `dispatches` | 子代理派遣 | 两边 | 10 / 100 / 1K / 10K 次 | CC：`Agent`（旧名 `Task`）工具调用；Codex：`spawn_agent` |
| `web-research` | 联网检索 | 仅 CC | 10 / 100 / 1K / 10K 次 | `WebSearch` + `WebFetch` 工具调用 |
| `file-edits` | 文件编辑 | 仅 CC | 100 / 1K / 10K / 100K 次 | `Edit` + `MultiEdit` + `Write` + `NotebookEdit` 工具调用 |

规则：
- 子代理派遣算主会话发出的调用；子代理再派出的不算。
- 联网检索和文件编辑都算子代理里的调用，因为这些也是在为你干活。这和工具类徽章排除子代理调用的规则不同，在说明里写清楚。
- Codex 本地记录里没有联网检索条目，所以 Codex 不做联网检索。
- Codex 已有「补丁」里程碑，所以 Codex 不做文件编辑。

## 3. 账本（每日汇总）新增字段

徽章不能因为原始记录被清理而消失，所以新条件都要能从每日账本算出来。每天新增：

| 字段 | 含义 |
| --- | --- |
| `activeMin` | 当天活动时间并集（分钟） |
| `maxParallel` | 当天最大同时活动会话数 |
| `midnight` | 当天 23:00 前开始、跨到次日 02:00 后的会话是否存在（记在开始那天） |
| `dispatches` / `webCalls` / `editCalls` / `autopilot` | 当天各计数 |

跨天的活动区间按日切开计入。旧账本里没有这些字段的日期按 0 处理；原始记录还在的日期会在下次采集时重新算出。

## 4. 顶级隐藏款

- 适用：CC 的会话数、工具调用、累计天数、协作时长、子代理派遣、联网检索、文件编辑；Codex 的线程数、补丁、累计天数、协作时长、子代理派遣。
- 做法：第 4 级的 `variants` 用 `tokenTopVariants(base)` 生成（象牙金星芒 / 黑金八角 / 蓝宝石星芒），门槛不变，原来的铂金造型被替换。
- `tokenTopVariants` 改名为 `topVariants`，挪到通用位置；`salt` 用 `<brand>/<id>`。
- Token 仍是第 5 级用三款随机，不变。

## 7. 造型：设计原则

不定外形白名单，定原则，在原则之内自由发挥（「随心所欲不逾矩」）。前三条写进了版式检查（`src/engine/layout.js`），新徽章不合规测试就失败。

1. **内外呼应**：内部结构跟着外形走。贴边的细描边沿外形内缩（`contour`），外形是什么形状，描边就是什么形状；圆形细描边只用在圆形徽章上。
2. **呼吸距离**：文字环、圆盘这些居中的大件，离外框（或贴边描边）的内沿至少留徽章半径的 6%。标准圆章（`roundMedal`）按外形的内切半径自动缩放内容，星形、花形、盾形不会贴边。
3. **轮廓节奏**：多边形最多 8 条边，再多就用圆形（16 边形看起来像一个抖动的圆）；可以用五边形。异形用少而舒展的起伏，一条轮廓里不同时出现尖角和圆弧；花形的凹口是圆角过渡，不是尖刺。
4. **系列感**：功能系列统一用圆角方形（App 图标家族）；其余系列按题材挑外形。

| 徽章 | Claude Code | Codex |
| --- | --- | --- |
| 跨日夜战 | 圆形表盘 | 圆形表盘 |

| 全勤月 | 尖顶六边形 | 八瓣花（印章） |
| 协作时长 | 圆形 + 60 道刻度表圈 | 平顶八边形 |
| 子代理派遣 | 八芒软星 | 五边形 |
| 联网检索 | 平顶八边形 | — |
| 文件编辑 | 五边形 | — |

## 8. 评审流程

1. 本地预览页（临时，不提交）：每枚新徽章、三种闪光材质、浅色陈列图都能点击放大、拖动旋转。
2. 用户逐枚反馈后修改，直到认可。
3. 定稿后删除预览页，再生成 `assets/*` 示例图。

## 9. 测试

- 每个新条件写单元测试，包括边界：
  - 22:59 → 02:01 解锁跨日夜战；间隔 61 分钟不解锁；
  - 第 20 个会话；
  - 恰好 3 个会话重叠；
  - 月末最后一个工作日；
  - 春节表内和表外年份；
  - 发布当年之前的生日不算。
- 账本测试：原始记录删除后徽章保留；旧账本缺字段不报错。
- 隐私测试：新字段里不出现工具参数、路径和昵称。
- 闪光：确定性（同输入同结果）；在大样本上比例约为 1/20；升级后保持。
- `check-shelf`：深色、浅色两张图都能生成，后台标签页也能完成。
- `publish`：README 片段替换的幂等性，包括从旧片段升级。
- 配置校验：所有新徽章、所有等级和变体都能通过 `validate`。
