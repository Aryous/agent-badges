# 架构审查问题修复 — 设计规格

- 日期：2026-10-22
- 状态：设计已确认，待评审规格
- 分支：`fix/review-findings`，从 `refactor/badge-renderer` 建出（统一渲染服务尚未合并到 main）
- 来源：独立 Opus 架构审查（2026-10-22）。审查提出 9 类问题，这里处理其中 8 类；Claude Code 采集的增量缓存暂不做

## 目标

修掉审查确认的问题，同时不改变任何不该改变的东西：

- 堵住会丢数据、占资源的缺陷：账本写入不安全、陈列墙显存不释放。
- 收回「文档就是代码」的可信度：注释和事实对得上，名字和内容对得上，同一件事只写一处。
- 页面层的检查进入 CI，不再只靠人在本机运行。
- 移除不该被跟踪的宣传片代码。

只有两处是有意的变化，其余外观、统计结果、命令行行为都不变：

- 大数字的显示格式统一为 K/M/B（第 5 节）。
- 程序员节背面刻字多一个撇号（第 2 节）。

## 执行方式

- 一份设计（本文件）、一份实施计划。计划里每节对应一个任务，共 8 个，按本文件的顺序执行。
- 每个任务由一个 Opus 子代理实现，再由另一个 Opus 子代理审查，审查发现的问题修完才进入下一个任务。全部完成后，再由一个 Opus 审查整个分支。
- 任务按顺序进行，不并行：多个任务会改同一批文档，并且共用同一个开发服务器拍对比图。
- 不推送、不发版。第 8 节验证 CI 时需要推送分支，那一步先征得用户同意。

## 每个任务共同的验收标准

1. `npx vitest run` 全部通过。
2. 按改动范围运行对应检查（见 AGENTS.md「Which checks to run」）：`npm run build`、`check:pack`、`check:browser`、`check:shelf`，以及 `build:site` + `check:site`。
3. 视觉回归：`node scripts/visual.mjs capture <新目录>`，再与基线 `compare`。结果必须逐像素一致，或者只出现本文件明确预期的差异；每一张差异图都要在任务报告里列出并说明原因。基线与比对必须同一天拍摄。
4. 涉及统计的任务，用改动前存下的统计基线对比统计结果，必须完全一致。基线工具：scratchpad 里的 `p2/dump-progress.mjs`，用 `p2/base/*.ledger.json` 计算，日期固定为 2026-10-21。
5. 文档同步：AGENTS.md、CONTRIBUTING.md、中英两份 README、`.agents/skills/add-badge/` 里凡是提到被改动内容的地方，同一个任务内改完；`tests/docs.test.js` 必须通过。

## 1. 宣传片移出版本控制

**背景**：宣传片的页面、逐帧录制脚本和配乐合成脚本，在 2026-10-19 被加入仓库，本不该被跟踪。从未提交过视频或音频文件。

**做法**

- 用 `git rm --cached` 停止跟踪这四项，并加入 `.gitignore`。本地文件全部保留：
  - `tools/promo.html`
  - `tools/promo/`
  - `scripts/promo.mjs`
  - `scripts/promo-audio.mjs`
- 不改写 GitHub 上的历史：已公开的两个提交保留。这些只是代码，不含密钥或视频；改写历史需要强制推送，无法撤销。
- 清除仓库对宣传片的依赖：
  - `filledState` 只被宣传片使用：从展示状态模块中删除，连同它的测试；宣传片本地文件里改回自己定义。
  - `scripts/visual.mjs` 不再拍宣传片的徽章墙，图片总数从 303 张变为 279 张。本任务结束时重拍基线。
  - AGENTS.md、CONTRIBUTING.md 删除宣传片相关内容，包括 Map 中 `tools/` 一行、约定 3 和约定 18 里的「promo」、脚本说明、开发页面列表。保留「不提交视频，`promo-out/` 被忽略」这条规则。
- 约定测试改为只扫描被 git 跟踪的文件（用 `git ls-files` 取文件列表）。否则同一个测试在本机能看到宣传片，在 CI 里看不到，两边结果可能不同。

**验收**：`git ls-files` 中不再有宣传片的文件；本机宣传片页面仍能打开；视觉回归在重拍基线前，对其余 279 张逐像素一致。

## 2. 命名整理

放在第二步，让后续任务都在最终的名字上进行。

### 2.1 拆分 `src/collect/`

- `src/collect/` 只保留「读取日志、写账本」：`claude-code.js`、`codex.js`、`common.js`、`index.js`。
- 新建 `src/share/`，存放把徽章分享出去的功能：
  - `card.js`：成就卡片 SVG
  - `public.js`：公开版数据过滤
  - `inject.js`：往网页注入数据
  - `publish.js`：发布到 GitHub
  - `receive.js`：接收页面交回的主页图
- `summary.js`（终端汇总文字）搬到 `src/cli/`。
- 分层规则：
  - `share` 只用 Node 内置模块，可以引用 `share`、`collect`、`data`、`brands`；
  - `cli` 增加可以引用 `share`；
  - 页面层（`viewer`、`app`）不引用 `share`。
- 同步更新：
  - 所有引用方：`src/cli/` 下的命令、`vite.config.js`、`scripts/assets.mjs`、`scripts/check-shelf.mjs`，以及相关测试；
  - `tests/contracts.test.js` 的分层表、`package.json` 的 `files`、`tests/package-files.test.js`；
  - AGENTS.md 的 Map 表和分层说明、CONTRIBUTING.md 的目录树。

### 2.2 其他改名

- `src/cli/app.js` 改名为 `src/cli/page.js`：它负责生成页面 HTML，原名和 `src/app/` 同名。
- `src/project/studio.js` 搬到 `tools/studio/`，和 `tools/studio.html` 放在一起。`src/project/logo.js`（项目标志）留在原处。
- `src/brands/shared/showcase.js` 改名为 `src/brands/shared/display-states.js`，函数名不变。`// showcase` 文件标记保持原样。AGENTS.md 约定 18 里「与 `// showcase` 标记无关」的解释随之删除。

### 2.3 删除 `titleEn`

- 现状：62 枚徽章里，61 枚的 `titleEn` 恰好等于 `en.title` 转大写（含 `{label}` 占位符的分级徽章，转大写后也一致）。唯一不同的是程序员节：`titleEn` 是 `PROGRAMMERS DAY`，`en.title` 是 `Programmers' Day`。
- 做法：
  - 删除全部徽章配置、项目标志、`appIcon()`、`featureBadge()` 里的 `titleEn`；
  - 在 `src/brands/shared/text.js` 提供一个函数，由 `en.title` 转大写得到这段文字；
  - 背面刻字、单枚查看里中文标题下的英文副标题都改用它；占位符替换的规则不变；
  - `validate.js` 不再要求 `titleEn`。
- 有意的变化：程序员节的背面刻字和英文副标题从 `PROGRAMMERS DAY` 变为 `PROGRAMMERS' DAY`。
- 文档：`add-badge` 技能（`SKILL.md`、`references/parts.md`、模板）和 CONTRIBUTING.md 删除 `titleEn` 的说明。

**验收**：视觉回归逐像素一致（背面刻字不在视觉回归范围内）；用 studio 渲染程序员节背面，确认只多了撇号；其余徽章的背面刻字文字与改动前逐字相同（比较 `engravingLines` 的输出）。

## 5. 大数字格式统一为 K/M/B

- 在 `src/data/format.js` 新建 `formatCount(n)`：
  - 规则：≥ 10 亿用 B，≥ 100 万用 M，≥ 1000 用 K，保留一位小数并去掉末尾的 `.0`，小于 1000 原样显示；
  - 不区分语言；
  - 进位要正确，例如 999,950 显示为 `1M`，不是 `1000K`。
- 以下三处改用它，各自原来的实现删除：
  - 成就卡片（`share/card.js` 的 `formatTokens`）；
  - 终端汇总（`cli/summary.js` 的 `fmt`）；
  - 网页（`viewer/i18n.js` 的 `formatBig`：陈列墙方块、单枚查看进度条、个人概览、热力图、分享海报）。
- 有意的变化：
  - 网页上 ≥ 1000 的数字由「1,234」变为「1.2K」；
  - 中文网页的「万」「亿」改为 K/M/B；
  - 终端「即将解锁」的十亿级数字由两位小数变为一位，例如 9.75B 变为 9.8B。
- 不变：徽章背面刻字使用原始数字，徽章外观不变。
- 视觉回归中，若主页图的文字含受影响的数字，主页图会出现差异，须在报告中说明。

**验收**：`formatCount` 有边界值单元测试（0、999、1000、999,950、1,234,567、9,750,000,000）；终端汇总、卡片的相关测试按新格式更新；视觉回归除上述说明外逐像素一致。

## 6. 账本和缓存的安全写入

**问题**（已复现）：

- `writeJSON` 直接覆盖文件，写到一半中断时，文件会被截断。
- 账本被截断后，这个工具每次采集都失败，却以退出码 0 结束；坏账本不会被修好，新数据也进不来。
- 进度文件被截断后，所有命令都会崩溃，只打印一行 JSON 解析错误。

**做法**

- 写入：所有数据文件先写入同目录的临时文件，再改名替换原文件。每次覆盖账本前，把当前版本保存为 `<文件名>.bak`。
- 读到损坏文件时：
  - **进度文件**（`<工具>.json`）：只用于对比「新解锁」，视为不存在，在终端提示哪个文件损坏，命令继续运行。
  - **账本**（`<工具>.ledger.json`）：不覆盖、不删除；该工具本次不采集，提示损坏的文件路径，以及从 `.bak` 恢复的完整命令；命令最终以非零退出码结束。
  - **Codex 缓存**：缓存可以重建，视为空缓存，重新解析。
- 文档：中英两份 README 的隐私和数据部分、AGENTS.md 的数据说明，提到 `.bak` 备份文件。

**验收**：测试在临时目录中复现三种损坏情形，确认处理结果符合上文；写入中断不会留下截断文件，用测试模拟写入失败，确认原文件完好。

## 7. 背面刻字推迟生成

**问题**：陈列墙为拍缩略图会组装当前工具的全部徽章并一直保留。每枚徽章的背面刻字有 3 张 1024×1024 贴图，按代码推算共约 512 MiB 显存，另外还有约 384 MiB 画布内存。而缩略图只拍正面，看不到背面。

**做法**

- 先实测改动前陈列墙的显存和贴图数量（`renderer.info.memory`，以及贴图尺寸的统计），确认推算属实。
- 陈列墙组装徽章时，背面先挂一组所有徽章共用的 1×1 占位贴图（标记为共享资源，`disposeBadge` 不释放）。这样材质的着色器与有刻字时相同，打开时只需更换贴图，不必重新编译着色器。
- 打开一枚徽章时生成刻字（现在打开时本来就会换成 2048 的清晰版本），关闭后释放刻字，换回占位贴图。
- 只有陈列墙这样做。studio、主页图等临时组装再立即释放的徽章，行为不变。

**验收**：

- 缩略图视觉回归逐像素一致；
- 新增「打开徽章并翻到背面」的截图，覆盖两个工具各若干枚，含分级、隐藏、未解锁的徽章，改动前后逐张对比一致；
- 报告改动前后实测的显存数字；
- `check:browser` 通过，其中包括打开、导出 PNG 和获得动画。

## 8. 浏览器检查进入 CI

**问题**：7 个脚本写死了 Mac 上的 Chrome 路径和只在 Mac 有效的显卡参数，页面层的检查无法在 CI 中运行。CI 现在只做构建、单元测试和打包检查。

**做法**

- 新建一个公共的浏览器启动函数（放在 `scripts/` 下），7 个脚本都改用它：
  - 默认按系统自动查找已安装的 Chrome，也可以用环境变量指定路径；
  - Mac 上继续使用真实显卡参数；Linux 上使用软件渲染。
- CI 新增：构建，启动开发服务器，运行 `check:browser`；运行 `build:site` 和 `check:site`。
- 像素级视觉回归依赖真实显卡，仍只在本机运行；AGENTS.md 写明这一点。
- 若软件渲染下有检查项因为速度或精度不稳定，可以为 CI 调整超时，但不得删减检查项；确需例外的，在报告中列出并说明原因。

**验收**：本机所有检查照常通过；把分支推送到 GitHub 后（推送前征得用户同意），CI 中新增的步骤通过。
