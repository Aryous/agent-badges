# 个人主页徽章墙（profile）— 设计规格

- 日期：2026-10-19
- 状态：已确认（全部公开 + 页面看不到的数据不放进网页）
- 相关：`shelf`（主页图片，见 2026-10-19-profile-shelf-design.md）、`export`（本机用的离线网页）

## 1. 目标

别人在 GitHub 个人主页点徽章图片，跳到这个人的 3D 徽章墙（GitHub Pages）。以后一条命令同时更新图片和网页。

## 2. 方案

- 图片和网页都放在主页仓库（`<user>/<user>`）根目录，在该仓库开启 GitHub Pages（main 分支、根目录），网址 `https://<user>.github.io/<user>/`。一个仓库、一次推送，两者一起更新。
- 新命令：

  ```
  npx agent-badges profile <主页仓库目录> [--name <名字>] [--lang en|zh] [--port] [--no-open]
  ```

  1. 采集本机数据。
  2. 写 `<目录>/index.html`：公开版徽章墙（见第 3 节）。
  3. 走 `shelf` 的浏览器流程，写 `<目录>/agent-badges-shelf.png`。
  4. 打印 README 片段（图片外面套 Pages 链接）和首次开启 Pages 的方法。
- Pages 网址从 `<目录>` 的 git 远端推出（只解析 `github.com/<owner>/<repo>`，不输出远端里的任何凭证）；推不出来时提示用户自己填。`--name` 默认用 owner。
- 命令不改 README、不提交、不推送。

## 3. 公开版网页

原则：**页面上看不到的，数据里也不放**（网页是公开仓库里的文件，F12 或直接看源码都能拿到全部内嵌数据）。

| 数据 | 处理 |
|---|---|
| 未解锁的隐藏徽章 | 不放进数据（页面本来显示 ???） |
| 更新时间 `generatedAt` | 只保留日期 `YYYY-MM-DD` |
| 每天的 Token 数和对话轮数 | 保留（热力图悬停会显示） |
| 徽章进度、解锁日期、等级数值 | 保留（页面会显示） |
| 详细账本（按小时活动、工具调用、模型 / MCP 哈希等） | 本来就不在网页数据里，保持不变 |

页面行为：

- 顶部来源文字：「Aryous 的徽章 · 更新于 10 月 19 日 · 生成你自己的 →」，链接到项目站点。
- 工具切换只列出有数据的工具，默认显示第一个；没有数据的工具不用示例数据冒充。
- 隐藏「GitHub 主页图」按钮（这是给本人用的）；分享海报保留。
- 页面语言跟随访客浏览器（中 / 英），可切换。

## 4. Agent 技能

「更新我 GitHub 主页的徽章」改用 `profile`：

1. 问主页仓库在哪（不猜、不搜磁盘）。
2. 第一次发布前告诉用户网页会公开每天的用量（热力图），并且旧版本会留在 git 历史里。
3. 运行 `npx -y agent-badges@latest profile <目录>`。
4. 提交和推送前先问用户；首次需要开启 Pages 时也先问。

`shelf` 和 `card` 保留，作为只要图片的选择。

## 5. 验证

- 单元测试：公开数据清洗（去掉未解锁隐藏徽章、时间只到日期、不含账本字段）；git 远端解析（https / ssh / 带凭证的 URL）；参数解析。
- 浏览器检查：公开版网页显示名字和日期、没有「GitHub 主页图」按钮、只列有数据的工具、F12 能拿到的数据里没有未解锁隐藏徽章。
- 用伪造数据跑完整的 `profile` 流程：两个文件都写出、打印的链接正确。
