# Token 徽章：行业通用口径下的新门槛、新金属与顶级彩蛋 — 设计规格

- 日期：2026-10-20
- 状态：已确认（在本地预览页逐项看过效果）

## 背景

Token 改成行业通用口径（输入 + 输出 + 缓存写入 + 缓存命中，与 ccusage、CC Switch 一致）后，数字约变成原来的 20–30 倍，原来的 1M / 10M / 100M / 1B 四级门槛太低。

## 门槛（两个品牌相同）

| 等级 | 门槛 | 金属 |
| --- | --- | --- |
| 1 | 10M | 铜 |
| 2 | 100M | 银 |
| 3 | 1B | 金 |
| 4 | 10B | 白金 |
| 5 | 100B | 三款彩蛋之一 |

## 金属颜色与光泽（所有徽章）

按真实金属重调：银更白更亮，金更饱满偏暖，铜更暖，白金是偏暖的灰白（与银分得开）。抛光金属粗糙度 0.16 → 0.12。灯光保持原样（试过摄影棚式反射环境，否决：釉面上出现玻璃般的反光条，「又像玻璃又像金属」）。

| 金属 | 色值 |
| --- | --- |
| 铜 bronze | `#D58C5F` |
| 银 silver | `#EEF0F2` |
| 金 gold | `#F2C46B` |
| 白金 platinum | `#CBC6BE` |

## 第 5 级：三款彩蛋，随机解锁一款

延续 Apple Watch 运动徽章的克制风格：不镶钻、不堆装饰，靠「异形外轮廓 + 特殊材质」区分。

| 款式 | 外形 | 材质与配色 |
| --- | --- | --- |
| 白瓷金 | 24 瓣花边 | 象牙白陶瓷底 + 金 + 深蓝珐琅圆盘 |
| 黑瓷金 | 八角形 | 蓝黑亮面底（`#1C2129`，不用纯黑）+ 金 + 墨绿珐琅圆盘 |
| 蓝宝石 | 16 角星芒 | 午夜蓝底 + 银 + 宝石蓝亮面珐琅圆盘 |

- 顶级更安静：底面和圆盘都不加纹理；里面的内容整体内缩，给异形外轮廓留出呼吸空间。
- 不用透明水晶：会把上面的浮雕折射出重影。
- 抽到哪一款：由「徽章的 salt + 达到 100B 的日期」哈希决定。同一个人永远是同一款，本地和 GitHub 主页一致；不需要额外存储，也不读任何隐私信息。两个品牌的 salt 不同，各抽各的。
- 近看时的说明里告诉用户这是彩蛋，以及抽到了哪一款；没抽到的不展示。

## Codex 圆盘的排法（5 级都改）

去掉代表 Token 的小方块，只留数字和缩小约三分之一的 Codex 图标，上下居中，四周留白。Claude Code 不改。

## 背面刻字与等级名

- 背面：不写金属名，改成「数字 · 日期」，第 5 级加款式名（「100B · 白瓷金 · 2026.10.20」）。理由：正面的金属和数字已经说明了级别；第 5 级的金属和等级不对应；数字比「金级」更有意义。
- 徽章墙卡片、主页图、等级阶梯：前四级仍写金属名，第 5 级写款式名；还没到第 5 级时写「隐藏款」。

## 引擎

- 分级的某一级可以带 `variants`：每款有 id、中英文名、金属、点缀色，以及可选的 `shape`、`layers`、`relief` 整体替换。
- `resolveTier(config, index, variant)` 先套用款式的替换，再替换 `$metal` 等占位符。
- 校验时每一款都要单独通过校验。
